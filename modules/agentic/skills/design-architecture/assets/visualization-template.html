Candidate 1 — Deepen a shallow boundary

Recommended. Editorial mass diagram: complexity the caller carries vs. complexity the module absorbs.

Files / modules

  • Step A
  • Step B
  • Deep module

Problem

The caller must know and sequence two steps itself; the thin wrapper hides nothing it does not already have to understand.

Solution

Absorb both steps into one module behind a single call, so the sequencing lives below the interface.

Benefits

  • Caller makes one call instead of coordinating two.
  • Sequencing can change without touching callers.
  • Cost: the module grows — confirm it stays one nameable job.

Candidate 2 — Point the dependency the right way

Alternative. Graph-shaped: dependency direction and what crosses each boundary.

Files / modules

  • Caller
  • Interface (caller-owned)
  • External API

Problem

The caller depends straight on the external API and speaks its wire format, so a change over there reaches the caller.

Solution

Put an interface the caller owns between them; the external format is produced below it, in one place.

Benefits

  • External format changes stop at the boundary.
  • The caller works in its own terms, not the wire's.
  • Cost: one more interface — justify it with a real second use or a volatile dependency.
